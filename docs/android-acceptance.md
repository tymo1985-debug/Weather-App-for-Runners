# Android acceptance checklist

Этот список относится именно к APK, собранному из `android/`, а не к PWA.

## Сборка и идентичность

- `applicationId`: `com.alextymoshchuk.runweather` — не менять без отдельного решения.
- `versionCode`: `1`; `versionName`: `1.0` — перед публичным выпуском повысить только
  после сверки с реально опубликованной версией.
- Debug APK собирается командой `./gradlew assembleDebug` после `npm run android-sync`.
- Release APK должен быть подписан исходным release-ключом. Ключ в репозитории
  отсутствует; без него нельзя обещать обновление установленной release-версии.

## Разрешения

- В manifest заявлены `INTERNET`, `ACCESS_COARSE_LOCATION` и
  `ACCESS_FINE_LOCATION`.
- Отказ от геолокации не блокирует приложение: остаётся ручной выбор города.
- Web Push/фоновые уведомления не следует считать нативно подтверждёнными, пока
  не подключён и не проверен соответствующий Android-плагин и сервер push.

## Обязательная ручная приёмка APK

- Прага → Берлин → GPS → перезапуск: сохраняются выбранный режим и активное место.
- Отказ в GPS: приложение остаётся рабочим и предлагает ручной выбор.
- Фон/возврат, системная кнопка Back и системные панели не ломают навигацию.
- Ширины 320, 360, 390 и 430 px, крупный системный шрифт и экранный диктор:
  нет перекрытий; кнопки имеют понятные имена и достаточную область нажатия.
- Офлайн-запуск после первого успешного запуска и восстановление сети показывают
  честное состояние сохранённых данных и обновляют прогноз.
- Импорт корректного и повреждённого GPX; файл больше 5 МБ отклоняется.
- Обновление поверх установленного APK проверяется только при совпадении
  `applicationId` и сертификата подписи.

## Автоматические проверки

- Модульные тесты охватывают неполные погодные данные, Run Score, DST, смену
  режима местоположения, соответствие кадров радара и ограничения GPX.
- Каждая кандидатная APK-сборка должна пройти `npm test`, `npm run android-sync`
  и `./gradlew assembleDebug`; release дополнительно — `./gradlew assembleRelease`.
